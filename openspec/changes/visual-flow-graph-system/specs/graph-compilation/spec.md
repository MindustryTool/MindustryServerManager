## ADDED Requirements

### Requirement: Full compiler pipeline
The compiler SHALL process documents through: parse → schema validation → link (resolve registry entries, select overload) → type check → thread-safety check → control-flow check → IR lowering → optimization → Java source generation → in-memory compilation → cached artifact. Each failing stage SHALL produce structured, node-scoped diagnostics and abort before later stages.

#### Scenario: Stage ordering enforced
- **WHEN** a document has both a type error and an invalid loop construction
- **THEN** diagnostics from earlier stages are reported first and no partial artifact is emitted

### Requirement: Generated code calls functions directly
Generated code SHALL invoke registered functions via direct generated calls (facade forwarders) or invokers bound once at load time; per-execution reflective `Method.invoke` dispatch SHALL NOT be used on hot paths.

#### Scenario: No reflection in generated bytecode
- **WHEN** compiled graph classes are scanned for `java.lang.reflect` dispatch of registered facade functions
- **THEN** none occur

### Requirement: Suspendable bodies compile to continuations
Graphs using Delay/Await SHALL compile to resumable continuation segments with explicit state slots rather than blocking threads; resume logic SHALL re-enter on the Mindustry main thread.

#### Scenario: Delayed graph does not hold a thread
- **WHEN** an execution suspends on a 5-second delay
- **THEN** no worker or main thread remains blocked during the wait

### Requirement: Content-addressed compilation cache
Compiled artifacts SHALL be cached under a key combining SHA-256 of the canonical logical document, compiler version, schema version, ABI version, and the registry fingerprint of consumed functions/events/properties; cache hits skip compilation entirely and survive server restarts. The cache is disposable derived data — the database graph document is always authoritative.

#### Scenario: Warm restart skips compilation
- **WHEN** an unchanged enabled graph loads after restart with a populated cache
- **THEN** the jar is loaded directly with zero compilation work

#### Scenario: Only changed graphs recompile
- **WHEN** one graph of ten is edited
- **THEN** exactly that graph's entry invalidates and recompiles; the other nine stay loaded

#### Scenario: Deleted cache self-heals
- **WHEN** the cache directory is cleared while graphs remain stored in the database
- **THEN** affected graphs recompile on next use with no data loss

### Requirement: In-memory compilation with JRE fallback
Compilation SHALL occur off the main thread into memory via `ToolProvider`; when unavailable on JRE-only hosts, a bundled Eclipse JDT compiler SHALL be used; absence of both SHALL produce a clear operator error rather than silent fallback interpretation.

#### Scenario: Headless JRE host compiles
- **WHEN** the plugin runs on a runtime without the system Java compiler
- **THEN** the bundled fallback compiles successfully and records which engine was used

### Requirement: Source map emission
Every compiled artifact SHALL include a source map mapping generated class/method/line ranges to node ids, function ids, and argument slots, persisted beside the jar in the cache entry.

#### Scenario: Error maps to node
- **WHEN** generated code throws inside the statement block of node `n7`
- **THEN** the reported error identifies graph `welcome-flow`, node `n7`, and the originating function

### Requirement: Atomic swap on recompile
Enabling or recompiling a graph SHALL load the new class fully, then atomically replace the live binding identified by a generation counter; executions already running on the old generation SHALL finish or be cancelled per policy, never executing half-swapped code.

#### Scenario: Hot recompile mid-execution
- **WHEN** a graph is recompiled while an execution is suspended in a delay
- **THEN** the old generation completes or cancels cleanly and the new generation handles subsequent triggers
